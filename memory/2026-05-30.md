## 2026-05-30 14:39 - 云同步功能重构完成

### 改动内容
重构云同步功能，改为**全自动 Token 驱动**模式：

1. **新增函数**
   - `initCloudSync()` - 首次使用时自动创建私有 Gist，保存 Gist ID 到浏览器本地
   - `ensureGistReady()` - 检查 Gist 是否已初始化，未初始化则自动初始化
   - `getLocalGistId()` / `saveLocalGistId()` - 本地 Gist ID 管理

2. **修改函数**
   - `syncToCloud()` - 支持两种模式：
     - 已初始化：直接 PATCH 更新已有 Gist
     - 未初始化：自动创建新 Gist 并保存 ID
   - `syncFromCloud()` - 自动读取本地保存的 Gist ID，构建 Raw URL
   - `saveSyncSettings()` - 只保存 Token，删除 rawUrl 逻辑
   - `toggleSyncPanel()` / `updateSyncStatus()` - 适配新 UI
   - `autoSyncFromCloud()` - 启动时自动拉取（如果有 Token）

3. **UI 改造**
   - 删除 Gist Raw URL 输入框
   - Token 输入框移到最上面
   - 新增"💾 保存 Token"按钮
   - 新增"🚀 初始化云同步"按钮
   - 简化提示文案，移除过时说明

### 使用流程
1. 用户去 GitHub 生成 Token（只需 gist 权限）
2. 在计算器页面点"云同步"，粘贴 Token，点"保存 Token"
3. 点"初始化云同步"，自动创建私有 Gist
4. 之后每次保存记录，自动同步到云端
5. 其他设备填同一个 Token，点"拉取"即可同步

### 安全性
- Token 只存在用户浏览器 localStorage
- 不上传给任何第三方
- Gist 默认私有（只有用户自己能访问）

### 经验教训（重要）
**部署文件 vs 源文件分离架构：**
- 源文件在 `workspace/` 下开发
- 部署文件在 `deploy/forging-tool/` 下
- 改完源文件后，**必须手动同步到部署目录**再 `vercel --prod`
- 否则 Vercel 部署的始终是旧版

**建议后续改进：**
