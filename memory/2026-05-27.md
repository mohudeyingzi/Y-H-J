## 锻件计算器自动填充修复 (14:10)

修复了 `forging-calculator-template.html` 中 `top_unitWt`（单重KG）自动填充卡中间值的 bug。

**问题**：用户逐步输入（先输直径+高度，再补余量）时，自动填充在第一步就设好值，后续余量变化无法更新。

**根因**：`calcAll()` 的自动填充条件 `manualUnitWt===null||manualUnitWt===0` 只在字段为空时触发。第一次完整计算填了中间值后，字段不再为空，后续不再更新。

**修复**：新增 `_unitWtDirty` 全局标记：
- 用户在 `#top_unitWt` 输入框手动编辑 → `_unitWtDirty=true` → 不自动覆盖
- 自动填充的值或字段为空 → `_unitWtDirty=false` → 随时更新为最新计算结果
- `resetAll()` 和 `loadRecord()` 中重置标记

修改涉及3处：全局变量声明、`oninput` 事件、`calcAll()` 条件判断。

## 锻件计算器删除重加后不显示结果修复 (14:12)

**问题**：删除某段后重新添加并填入尺寸，后面的结果（尺寸和重量）不自动显示。

**根因**：`calcAll()` 用数组下标 `i+1` 作为写入目标的 DOM ID，而非段落的实际 DOM ID。
- 例：段1、段2 → 删段1 → 加新段（ID=3）→ 数组 [段2, 段3] → 写 `cyl_tsize_1`（不存在）、`cyl_tsize_2`（只有段2的结果被更新）

**修复**：
1. `collectSeg()` 增加 `r.id=id` 返回实际 DOM ID
2. `calcAll()` 中 cyl/rect/hole 循环改用 `ti=c.id` / `ti=r.id` / `ti=h.id` 替代 `ti=i+1`

这样结果元素 ID 与实际段落的 DOM ID 始终保持一致。
